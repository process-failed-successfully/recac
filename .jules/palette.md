## 2026-05-15 - Prevent Empty Modals for Whitespace API Responses
**Learning:** In the Web UI, API responses for AI-generated text fields (like explanation, changelog, and postmortem) can sometimes return strings containing only whitespace characters. Checking just for truthiness (`if (data.explanation)`) fails to catch this, leading to the UI rendering a blank, confusing modal instead of the helpful empty state ("No explanation provided").
**Action:** Always include a `.trim() !== ''` check when evaluating text responses from external APIs (especially LLM-generated ones) before attempting to render them into text nodes, ensuring users always see a meaningful empty state when content is functionally missing.
## 2026-05-14 - Web UI Form Accessibility for Actionable Inputs
**Learning:** In the orchestrator Web UI, search and filter inputs (`job-search`, `job-state-filter`) were grouped in a `<div>` with a companion `<button>` running a custom `keyup` event listener for 'Enter'. This broke native keyboard submit accessibility, required custom JS, and failed to correctly link the submission to the loading state built into the button.
**Action:** When building interactive components in web UIs, always wrap grouped actionable inputs inside a native `<form>` tag and use a standard `<button type="submit">`. This preserves default browser behavior (like pressing 'Enter' anywhere in the form to submit), simplifies event handling, and guarantees assistive technologies can announce and interact with the form properly.
## 2026-05-15 - Adding Inline Copy Functionality to Table IDs
**Learning:** Users of the Orchestrator frequently need to copy Job IDs from the dashboard to grep logs or query the API. Rendering IDs as plain text forces manual selection. Making the ID a transparent, styled `<button>` that copies to the clipboard natively solves a major friction point.
**Action:** When displaying critical unique identifiers (like IDs, hashes, or trace keys) in a data table, convert them into accessible button elements (`background: none; border: none; text-decoration: underline;`) with an `onclick="navigator.clipboard.writeText(...)"` handler that provides inline, immediate visual feedback (e.g., temporarily changing the text to 'Copied!').
## 2026-05-15 - Enhancing Icon-Only Button Discoverability
**Learning:** In the Orchestrator web UI, while icon-only buttons (like the `&times;` close button in modals) properly used `aria-label` for screen reader accessibility, they lacked visual tooltips for mouse users. This meant users hovering over the `X` or remove icons had no explicit confirmation of the action or knowledge of associated keyboard shortcuts (e.g., the Escape key for modals).
**Action:** Always pair `aria-label` with a visual `title` attribute for icon-only buttons (like `&times;` close buttons or removal icons) to provide tooltips for mouse users. Include any associated keyboard shortcuts in the tooltip text (e.g., `title="Close (Esc)"` or `title="Shortcut: 's'"`) to aid discoverability.
## 2026-05-26 - Actionable Empty States
**Learning:** Empty states in modals with passive text instructions like 'Press Esc to close' force users to guess interactions or rely purely on keyboard shortcuts. Replacing them with explicit, actionable CTA buttons (like `<button onclick="...close...">Close (Esc)</button>` or `<button>+ Submit Job (s)</button>`) makes the UI immediately discoverable and accessible, especially for mouse users or those unfamiliar with the app's shortcuts.
**Action:** When designing or refactoring empty states, always prioritize actionable buttons that directly trigger the suggested resolution or close action over passive text instructions.
## 2026-05-27 - Explicit Empty States in Data Tables
**Learning:** In the Orchestrator web UI (`internal/web/static/index.html`), dynamically rendered data tables (like `#features-table`) lacked explicit empty states when the underlying data array was empty. This left users with a confusing blank table.
**Action:** Always implement an explicit empty state (e.g., a full-width table row displaying a 'No data found' message) when iterating over data arrays to render table rows, ensuring users are not left guessing whether data is loading or missing.

## 2024-05-18 - Accessible Loading and Error States in Dynamic Tables
**Learning:** When fetching data for dynamic tables, `<tbody>` empty or loading states must be explicitly handled, otherwise screen reader users face confusing blank tables or sudden layout shifts. Wrapping `<tbody>` with `aria-live="polite"` helps announce when data finally populates or fails, and keeping inline styles out of `<tbody>` elements improves maintainability and satisfies memory constraints.
**Action:** Always provide explicit HTML structure (like an initial `<td colspan="...">Loading...</td>` row) for dynamic tables, add `aria-live="polite"` to the table body, and use CSS classes instead of inline styles for rendering both empty messages and error states.
## 2026-06-04 - Avoid Inline Styles on Interactive Elements
**Learning:** In the Orchestrator web UI, inline styles (`style="background: none;..."` or `el.style.cssText`) were used on the interactive "Copy ID" buttons. This approach makes it impossible to apply pseudo-classes like `:hover` and `:focus-visible`, which are essential for accessibility, providing clear visual feedback for mouse users and explicit focus indicators for keyboard navigation.
**Action:** When building or refactoring interactive components in web UIs, always avoid using inline styles. Instead, define semantic CSS classes in the global `<style>` block or external stylesheets to ensure pseudo-classes and full accessibility states can be properly implemented.
## 2026-06-06 - Actionable Error States over Passive Text
**Learning:** In the Web UI, error states that display passive text instructions like "Please try refreshing" force the user to figure out the browser's reload mechanism, breaking the app experience.
**Action:** When handling error states for async operations (like data fetching), always replace passive text instructions with an explicit, actionable `<button>` (e.g., `<button onclick="loadData()">Retry</button>`) to keep the user engaged in the UI flow and provide an immediate resolution path.
## 2026-06-07 - Actionable Empty States and Consistent Error Styling
**Learning:** In the Orchestrator web UI, passive empty states and disjointed error styling across different DOM elements lead to a degraded user experience. An empty graph response rendering as a blank box, or an error displaying without the standard red background, feels broken. Furthermore, failing to check for empty or whitespace-only API responses before processing them can lead to rendering raw HTML or blank spaces.
**Action:** Always replace passive text empty states with actionable buttons (like 'Refresh'). Consistently apply the standard error styling class (e.g., '.error-message') to all dynamically injected error states, regardless of which container they target. Always add explicit '.trim() === ""' checks for external API text responses to ensure functional empty states are shown when content is missing.

## 2024-06-08 - Global Action Refresh Button and Shortcuts
**Learning:** For async operations attached to global actions like "Refresh Dashboard", preventing duplicate submissions and clearly conveying the loading state (`aria-busy="true"`, disabled styling, "Refreshing..." text) is essential for screen readers and impatient users. Implementing simple global keyboard shortcuts (like 'r' for refresh) enhances power-user experience but requires checking that the focus is not inside form inputs to avoid unintended triggers.
**Action:** Always provide explicit disabled and `aria-busy` states for global async action buttons, and safely scope keyboard shortcuts by verifying `e.target.tagName` excludes 'INPUT', 'TEXTAREA', and 'SELECT'.
## 2026-06-09 - Adding Spinners for Async Operations
**Learning:** Users lack confidence when actionable buttons like 'Refresh' provide only text changes without visual motion during async operations, making the app feel frozen.
**Action:** Always include a visual animation like a rotating spinner alongside accessible ARIA states for async buttons and table loading rows.
## 2026-06-11 - Synchronize Visual Updates with ARIA Labels
**Learning:** Visual state changes on interactive elements (like a "Copy" button changing its text to "Copied!") are not naturally announced to screen reader users if an overriding, static `aria-label` exists on the element. In these scenarios, updating only the `innerText` provides visual feedback but fails accessibility.
**Action:** Always ensure that when dynamic text state changes occur on interactive elements using `aria-label`, the `aria-label` is synchronously updated and eventually reverted along with the visual text (e.g. updating the label to "Copied ID").
## 2026-06-12 - Humanizing Machine Enums in the UI
**Learning:** Raw API enums (like `in_progress` or `needs_review`) render poorly in user interfaces and feel unpolished. Users expect standard text styling (capitalization and spaces). Displaying machine representations directly exposes implementation details and hurts the UX quality.
**Action:** Always format raw API enum strings in status badges or data tables by replacing underscores with spaces via JS string replacement (`.replace(/_/g, ' ')`) and applying CSS `text-transform: capitalize;` to ensure human-readable content.

## 2026-06-13 - Format Metadata Enums with Badges
**Learning:** Rendering enum-like metadata (such as "Priority") as plain text within data tables reduces readability and scannability, making it harder for users to quickly parse the information compared to explicit status columns.
**Action:** Always format API enums (like priority levels) using consistent neutral badges (`status-badge status-pending` for example) and replace underscores with spaces (`.replace(/_/g, ' ')`). Additionally, always provide an explicit text fallback (like 'unassigned') for empty values instead of rendering blank table cells.
## 2026-06-14 - Smooth Transitions on Table Rows
**Learning:** In the Orchestrator web UI, applying CSS 'transition' directly to the 'table' element does not properly animate background color changes on 'tbody tr:hover'. The transition needs to be applied directly to the target element undergoing the state change.
**Action:** When applying CSS transitions for hover effects on table rows, apply the 'transition' property directly to the row elements (e.g., 'tbody tr') rather than the parent 'table' element to ensure smooth visual animations.
## 2026-06-17 - Accessible Refresh Timestamps
**Learning:** In the Orchestrator web UI, when implementing global async data refresh actions (like clicking a Refresh button), relying solely on the loading spinner and button state changes can leave users unsure when the data was last updated, and fails to provide a clear completion announcement for screen readers.

## 2026-06-18 - Preserve Focus During Async Operations and DOM Destruction
**Learning:** In the Orchestrator web UI, applying `disabled = true` to global action buttons (like 'Refresh') during async operations causes the browser to drop focus to the `<body>`. Furthermore, dynamically generating 'Retry' or 'Refresh' buttons in empty/error states and then destroying their parent container via `.innerHTML` immediately drops keyboard focus. This creates a severe accessibility issue where keyboard users must manually tab entirely back through the page.
**Action:** Always use `aria-disabled="true"` instead of the `disabled` property for async action buttons to preserve focus state while mimicking disabled styling (`[aria-disabled="true"]`). Additionally, before aggressively destroying DOM content (via `.innerHTML`), explicitly rescue focus by moving it to a stable, related element (like the main refresh button) if the `document.activeElement` is within the target container.
## 2026-06-21 - Respecting OS Reduced Motion Settings
**Learning:** Adding animations (like `.spinner`) and CSS transitions for interactive elements without honoring the user's OS-level accessibility settings (e.g. `prefers-reduced-motion`) can cause severe issues for motion-sensitive users. This often results in nausea or dizziness for users who rely on reduced motion for safe internet browsing.
**Action:** Always include a `@media (prefers-reduced-motion: reduce)` block in the global CSS to disable infinite CSS animations (like spinners) and neutralize transition effects (like `:hover` transitions) on UI elements for affected users.
## 2026-06-25 - Handle Asynchronous Clipboard Rejections
**Learning:** In the Orchestrator web UI, calling `navigator.clipboard.writeText()` without `await`ing it or handling potential rejections leads to a broken UX. Browsers will reject the promise if the user denies clipboard permission or if the app is not running in a secure context, resulting in a silent failure where the UI claims "Copied!" but nothing was actually copied.
**Action:** Always `await` clipboard operations and wrap them in a `try...catch` block. When copying fails, update the UI to provide explicit visual failure feedback (e.g., changing text to "Failed!" and updating `aria-label`/`title`) so users aren't left confused.
## 2026-06-27 - Semantic Page Structure and Responsive Tables
**Learning:** In the Orchestrator web UI, organizing content with generic `<div>` elements hides the page structure from screen readers, while missing responsive wrappers around data tables causes horizontal overflow and layout breakage on smaller screens. Additionally, global CSS rules (like `margin-top: 10px` on `.action-btn`) can unintentionally break flexbox alignments in completely different contexts (like header toolbars).
**Action:** Always use semantic HTML5 landmarks (like `<header>` and `<section aria-labelledby="...">`) to create a clear document outline for assistive technologies. Ensure wide data tables are wrapped in a container with `overflow-x: auto` to prevent responsive layout issues. Keep generic component CSS minimal and scope layout-specific properties (like margins) to the context where they appear (e.g., `.empty-message .action-btn { margin-top: 16px; }`).
## 2024-07-28 - Flaky Unit Tests and Context Clashes

**Action:** Always ensure properly synchronized channel waits (`<-ch`) combined with isolated test logic inside `Run` closures on `mock.On` hooks when asserting background evaluation behavior over `time.Sleep`.
## 2026-06-28 - Explicit Table Layout Constraints and Overflow Handling
**Learning:** In the Orchestrator web UI, applying \`table-layout: fixed\` with explicitly sized columns (e.g. via explicit \`width\` classes) prevents columns from arbitrarily reflowing or squishing together when a specific column like "Description" contains a massive string. Combined with \`overflow-wrap: break-word\` applied to cells, long strings safely break lines inside their fixed constraints, keeping the table readable. Additionally, wrapping the table with an explicit \`aria-labelledby\` points screen readers to the section's descriptive heading, providing critical context lacking in default \`table\` semantic boundaries.
**Action:** When building data tables, always enforce \`table-layout: fixed\`, assign proportional width classes to columns, enforce \`overflow-wrap: break-word\` on table data, and explicitly label the table using \`aria-labelledby\` targeting a descriptive heading to guarantee semantic context and visual stability regardless of the data length.
